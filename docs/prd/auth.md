# Auth [auth] (PRD §4.1)

Baca juga: `../PRD.md`, `security.md`.

- Login/logout admin & merchant; password hashing modern; MFA admin wajib, merchant owner direncanakan; RBAC granular; session/token bisa dicabut + expiry jelas; rate limit + audit di login & aksi sensitif; sandbox & production terpisah.
- **Panel platform DEWA (14 Okt 2026):** DEWA = Platform Admin di panel khusus `/platform` (lihat `platform-panel.md`) — cookie terpisah `erapay_platform_session` (Path=`/platform`, HttpOnly), rute `/v1/platform/*` di balik `requirePlatformAdmin` (DEWA saja: `rbac:manage`, tanpa merchant). Login `/v1/platform/auth/login`, MFA `/v1/platform/auth/mfa/verify`; akun non-DEWA ditolak `401` identik dan sesinya dicabut. RBAC dipindah ke `/v1/platform/admin/*` (migrasi `0019` menghapus `/dashboard/admin/access` dari menu). Bootstrap pertama via `/platform/setup` + `ERAPAY_PLATFORM_SETUP_TOKEN` (≥ 32 karakter, atomic, sekali saja) memakai `auth.CreatePlatformAdmin`. Super admin/finance/ops tetap di dashboard memakai `erapay_session`.
- **Daftar merchant mandiri (12 Okt 2026; data diri 14 Okt 2026):** `POST /v1/auth/register` (publik, tanpa sesi) membuat user + merchant `submitted` + outlet + keanggotaan `merchant_owner` dalam satu transaksi. Body wajib memuat `identity` (data diri DOKU-style, lihat `merchant.md`): `id_number` (NIK 16 digit), `place_of_birth`, `date_of_birth` (YYYY-MM-DD, usia 17–120), `gender` (male/female), `address`; `npwp` opsional (15–16 digit); `business_npwp` + `business_nib` wajib untuk `account_type=business` (dan ditolak untuk individual). Titik/spasi dinormalisasi. Pembayaran dan payout sudah menolak merchant yang bukan `approved`. Review lewat `GET/POST /v1/admin/merchants…` (izin `merchant:review` untuk melihat, `merchant:approve` hanya `super_admin` karena persetujuan menetapkan tarif; sesi merchant selalu ditolak). Kebijakan kata sandi: 12–128 karakter (`auth.ValidateNewPassword`, satu kebijakan untuk daftar dan reset). Rate limit lewat `internal/throttle` (tabel `register_attempts`): daftar 5/IP/jam (`ERAPAY_REGISTER_PER_IP_HOUR`); kirim ulang verifikasi dan lupa sandi 10/IP dan 3/email per jam. Jawaban daftar (202), kirim ulang, dan lupa sandi identik untuk email terdaftar maupun tidak (anti-enumerasi; pemilik email terdaftar diberi tahu lewat email). Daftar juga wajib `ERAPAY_ENCRYPTION_KEY` (tanpa kunci, NIK/NPWP tidak bisa disimpan terenkripsi → rute `register` tidak dipasang, `CanRegister()` false).
- **Identitas merchant (14 Okt 2026):** `GET /v1/merchant/identity` (sesi merchant, `merchant:read`) menampilkan data diri ter-masking + kelengkapan; `POST /v1/merchant/identity` (sesi merchant, `merchant:write`) mengisi/memperbaiki data selama status `submitted`/`under_review`/`action_required`. Merchant dari ARUS atau yang dibuat sebelum fitur ini (identitas kosong) menyelesaikannya lewat sini; `merchant_id` selalu dari sesi. `approve` ditolak (`IDENTITY_INCOMPLETE`) sampai lengkap.
- **Verifikasi email dan reset sandi (12 Okt 2026):** token acak 256-bit, hanya sha256 yang disimpan (`email_tokens`), sekali pakai (UPDATE atomik), kedaluwarsa (verifikasi 48 jam, reset 1 jam), kirim ulang menggantikan token lama. Halaman web `/verify-email` hanya menampilkan tombol; token baru dipakai saat POST, supaya pemindai tautan tidak menghabiskannya. Reset menutup semua sesi, ikut memverifikasi email, dan mengirim pemberitahuan "kata sandi diubah"; sandi yang ditolak (terlalu pendek) tidak menghabiskan token. `approve` merchant ditolak (`EMAIL_NOT_VERIFIED`) sampai email pemilik terverifikasi, dan (`IDENTITY_INCOMPLETE`) sampai data diri lengkap. Akun dari `bootstrap` dan akun yang ada sebelum migrasi 0014 dianggap terverifikasi.
- **Status review:** `submitted → under_review` (`start-review`), `→ action_required` (`request-changes`, catatan wajib; izin `merchant:review`), pemohon menjawab lewat `POST /v1/merchant/resubmit` (sesi merchant, izin `merchant:write`, hanya dari `action_required`, merchant dari sesi). `approve`/`reject` (izin `merchant:approve`, `super_admin`) boleh dari ketiga status itu.
- **Email keluar:** `internal/mailer` (SMTP: STARTTLS atau TLS 465, menolak plaintext ke host non-lokal dan injeksi header). Tanpa `ERAPAY_SMTP_HOST` di luar development, endpoint daftar/verifikasi/reset tidak dipasang.
- API key: prefix publik, secret tampil sekali, disimpan hash, revoke/rotate, scoped.
